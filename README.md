# SmartBank – Java + MySQL College Project

A fictional educational banking application inspired by the broad navigation and clean layout patterns of Indian retail banking websites. It is not affiliated with SBI or any real bank.

## Technology
- Java 17, Spring Boot, JDBC
- MySQL 8+
- HTML, CSS, JavaScript
- Maven

## Requirements
Install Java 17+, Maven 3.8+, and MySQL 8+.

## Configure database
1. Start MySQL.
2. Create a database (optional; the JDBC URL creates it if the MySQL user has permission):
   `CREATE DATABASE smartbank;`
3. Set credentials before running:
   - Windows PowerShell:
     `$env:DB_USERNAME="root"; $env:DB_PASSWORD="your_password"`
   - macOS/Linux:
     `export DB_USERNAME=root`
     `export DB_PASSWORD='your_password'`
4. If needed, edit `src/main/resources/application.properties`.

The schema is initialized automatically on startup. Existing tables/data are retained; `CREATE TABLE IF NOT EXISTS` does not erase records.

## Run
From the project root:
```bash
mvn spring-boot:run
```
Open `http://localhost:8080`.

## Demo flow
1. Open account and register a demo customer.
2. Sign in.
3. Deposit or withdraw demo funds.
4. Register a second demo customer to create a recipient account.
5. Transfer between accounts and inspect transaction history.

## API endpoints
- `POST /api/auth/register`
- `POST /api/auth/login`
- `POST /api/auth/logout`
- `GET /api/dashboard`
- `POST /api/deposit`
- `POST /api/withdraw`
- `POST /api/transfer`
- `GET /api/transactions?accountNumber=...`

Authenticated routes use `Authorization: Bearer <token>`.

## OOPS concepts for viva
- Encapsulation: private fields in `BankAccount` and `Customer`.
- Abstraction: abstract `BankAccount`.
- Inheritance: `SavingsAccount` and `CurrentAccount` extend `BankAccount`.
- Runtime polymorphism: overridden account methods.
- Composition: `BankAccount` owns a `TransactionHistory`.
- Constructors: default and parameterized constructors in account classes.
- Static members: account-number sequence and account count (in the in-memory console model; database IDs are generated by MySQL).
- Method overloading: `deposit(amount)` and `deposit(amount, description)`.

The REST/controller/service/DAO-style separation also demonstrates object-oriented responsibility boundaries.

## Important limitations
This is a student demonstration, not production banking software. It does not connect to payment rails, UPI, cards, KYC, or real bank systems. Session tokens are held in application memory and expire when the server restarts. For production, add Spring Security, HTTPS, secure session lifecycle, CSRF protection, rate limiting, audit controls, stronger account authorization, monitoring, backups, and a professional security review. Do not deploy this publicly or use real customer data.
